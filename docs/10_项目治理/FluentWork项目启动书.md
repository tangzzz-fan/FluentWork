## 一、项目一句话

用 8 周时间交付 FluentWork iOS MVP 并启动 20 人内测，验证唯一核心假设：**"用户投喂真实工作素材 → AI 生成练习 → 说-读-炼化-闪测-语料库闭环"能带来周 3 次以上的持续练习**（北极星：周完整流水线完成率 ≥ 40%；并列核心信号：周练习次数 ≥3 次的用户占比——每周只完成 1 次流水线不足以证实"持续练习"假设，内测复盘两个数一起看）。

## 二、项目治理原则（先定规矩再干活）

1. **单一事实源**：产品需求以 PRD 为准，技术实现以技术方案为准，排期以本启动书为准。口头结论不算数，结论必须落到对应文档的修订记录里。
2. **Go/No-Go 文化**：W2 语音压测不达标就停下来调头，不带病前进。任何里程碑不达标，先评审再决定延期还是砍范围，禁止静默滑期。
3. **范围冻结与变更流程**：MVP 范围以 PRD V1.4 为准。新需求一律进 Backlog 池，只有"影响核心假设验证"或"阻断发布"的变更才允许插入，需 CTO + PM 双签。
4. **小步快跑**：每周五 Demo 日，必须演示真机上可运行的东西，不允许用 PPT 代替进度。

## 三、角色与分工（RACI）

| 角色 | 人员 | R（执行） | A（负责） |
|---|---|---|---|
| 产品负责人 PM | 1 人 | PRD 维护、内测运营、数据分析、用户访谈 | 范围、优先级、验收 |
| CTO / 技术负责人 | 1 人 | 架构评审、Go/No-Go 决策；音频引擎/网关状态机/调度引擎关键路径手写 | 技术方案、排期、质量红线 |
| 设计（可兼职） | 1 人 | 高保真稿、动效规范、语音状态机原型 | — |
| AI Agent 集群 | 正式产能 | iOS UI/后端 CRUD 与网关协议层/测试/标注/评估/内容/文档 | —（产出均过人类门禁，见《团队分工文档》） |

人力基线说明：人类团队为 1 名产品/技术负责人（PM 与 CTO 可同人兼任）+ 设计兼职，AI Agent 为正式产能而非辅助工具；分工矩阵、门禁与周对齐见《FluentWork团队分工文档》。
人员不足时的优先级铁律：**保语音链路和核心闭环，砍管理后台与运营工具的精致度**（后台能用命令行/简单页面解决就不做 UI）。

## 五、全流程阶段与里程碑排期

### 阶段总览

```
M0 启动(W0) → M1 技术验证(W1-W2) → M2 核心链路(W3-W5) → M3 闭环成型(W6-W7) → M4 内测(W8 起, 4周) → M5 复盘决策(W12)
```

### M0 启动（W0，本周）

| 事项 | 产出 | 负责人 |
|---|---|---|
| Kickoff 会：本文档评审通过 | 启动书 V1.1 签收 | 全员 |

### M1 技术验证（W1-W2）——全项目唯一的技术生死关

| 事项 | 出口标准 |
|---|---|
| 语音网关 POC + 火山端到端打通 | 真机可对话 |
| iOS 音频引擎 POC（AVAudioEngine + AEC + 打断） | 外放场景识别无污染 |
| **压测报告**：首响 P90、中式口音 WER、外放 AEC、打断响应 | **Go/No-Go 评审：首响 P90 ≤ 1.5s 且 WER 达标** |
| 服务端骨架（CI/埋点/ai_cost_logs） | 成本埋点上线 |

**Go/No-Go 预案**：延迟不达标 → 切模块化编排形态重测（+1 周预算内）；WER 不达标 → 评估双 ASR 供应商策略；两项都不达标 → 项目暂停重估，不硬推。

### M2 核心链路（W3-W5）

| 周 | 交付 | 里程碑出口 |
|---|---|---|
| W3 | 接口契约冻结；说的房间主链路；Prompt 评估集建立 | 真机完成完整对话并落库 |
| W4 | 创建练习弹层、业务服务骨架、管理后台雏形 | 素材 → 对话全链路通 |
| W5 | 异步管线（评价/炼化/命中检测）、回顾页、游客身份与归并 | **说 → 读 → 入库打通（Demo 日演示）** |

### M3 闭环成型（W6-W7）

| 周 | 交付 | 里程碑出口 |
|---|---|---|
| W6 | 语料库、每日一读；隐私政策定稿 | 语料库与每日一读全流程通过（订阅内购后置 V1.1） |
| W7 | 闪测调度引擎、话题卡、APNs 推送、降级开关、Oncall 手册；**周末提交 feature-complete 构建提审 TestFlight** | **完整闭环打通（全链路 Demo）+ 提审已提交** |

### M4 内测（W8 起，4 周）

- W8：TestFlight 审核问题修复（外部测试同样走基础审核，通常 1-3 天且可能被打回，故提审提前到 W7 末）+ 20 人内测启动（招募自 W0 启动，签署内测协议）；
- 内测期机制：每日站会看数据看板（北极星、漏斗、延迟红线、成本），每周五迭代一个小版本，第 2/4 周出《内测数据复盘报告》；
- **内测期不做新功能**，只做质量修复和 Prompt 调优（Prompt 调优走评估集回归流程）。

### M5 复盘决策（W12）

依据两份复盘报告做三选一决策（复盘时北极星与"周练习 ≥3 次占比"两个数一起看，见 PRD §十一）：

| 信号 | 决策 |
|---|---|
| 北极星 ≥ 40% 且转付费信号正向 | 进入 V1.5（听力/写模块/闪测层级 2-3），规划 App Store 正式发布 |
| 完成率 20-40%，卡点明确 | 针对性迭代一轮（4 周）后复测 |
| 完成率 < 20% | 项目复盘，保留语料库/调度资产，重估方向——不追加投入 |
